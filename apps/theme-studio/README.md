# Theme Studio

面向当前 `@aifuxi/semi-ui-vue` 的独立主题工作台。它是 monorepo 内的私有 Vue/Vite 应用，与 `apps/docs` 平级，不依赖文档站布局、DemoBlock、路由或状态。

## 启动与构建

在仓库根目录使用 mise 锁定的 Node/pnpm 环境：

```sh
# 首次运行或公开包源码变化后，准备实际消费的公开包与编译 CSS。
pnpm theme-studio:prepare
# 独立开发服务；严格使用 4322，端口占用时直接报错。
pnpm theme-studio:dev
# 类型检查并生成 apps/theme-studio/dist，可单独静态托管。
pnpm theme-studio:build
# 正式 Chromium 生产页面回归；自动使用 4324，不占用开发端口。
pnpm test:theme-studio
```

开发入口为 `http://localhost:4322/#/tokens`。WebStorm 可复用 `pnpm theme-studio:dev` 运行配置。`package.json` 的应用身份为 `@workspace/theme-studio`，`private: true`，不进入 npm 发布；`preview` 使用 4322，`clean` 只移除本应用 dist。构建使用普通 Vue/Vite 插件，用户定制主题不需要 Sass 或专用主题插件。

`base: './'` 与 hash 路由支持独立域名或静态子目录部署，无需服务器配置 history 回退。文档站通过构建环境变量 `VITE_THEME_STUDIO_URL` 配置工作台部署根地址；不设置时指向上述本地服务。开发与正式测试均不隐式重建公开包，冷启动先执行 prepare；源码类型检查通过 tsconfig paths 指向 workspace 自有源码，运行页面仍通过真实公开 exports 消费已构建的包。

## 开发迭代反馈

工作台源码和样式通过已有 Vite 开发服务热更新，修改后立即查看页面，生效不等待类型检查、构建或测试。仅改 `apps/theme-studio/src` 不需要重复 prepare 公开包。先说明页面已更新，再执行与改动相关的检查；同一变更不在定向测试通过后无依据地重复完整回归。跨工作台的主题边界变更再运行一次完整 Theme Studio 回归，不运行整库矩阵。

变量编辑只在提交边界校验一次原值，引用展开后仅补充必要的类型检查。会话校验和 CSS 引用查找复用 Map，渲染和 CSS 生成不重新校验已接受的数据。导入文件仍在进入会话时验证结构与引用，避免部分应用。

## 工作台能力

Theme Studio 使用本项目的 CSS token 体系组织设计与预览。DSM 仅作为功能参考，界面不复刻其 SCSS 工作流，也不包含作者、账户或主题包发布信息。

| 路由            | 能力                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `/#/tokens`     | 基础色阶、语义色、字体排版、圆角、间距、阴影、动效；按名称搜索、筛选已修改变量、逐项复原、CSS 引用与反向引用、颜色选择器及 WCAG 2 对比度检查 |
| `/#/components` | Button、Input、Select、Tag、Card、Table、Modal、Tooltip 的实际属性编辑与状态预览                                                             |
| `/#/preview`    | 组件总览、文字排版、阴影与交互、数据表单、数据表格与局部主题对照；同一编辑会话下切换深浅模式                                                 |

全局颜色与排版的默认值固定对齐 Semi `v2.102.0`。目录从公开 `base.css` 读取原始变量，不复制 vendor、不用颜色算法重建固定基线。用户编辑品牌后才调用公开颜色生成器。品牌 HEX 支持 `#RGB`、`#RRGGBB` 且必须有色相；普通语义颜色变量支持 CSS 颜色、透明度和已知变量引用。基础色阶保持 Semi 的逗号分隔 RGB 通道格式，颜色选择器会自动转换。

深浅模式各自保存变量覆盖；品牌和基础排版便捷设置共用原有公开主题能力。单项覆盖优先于便捷设置。撤销/重做覆盖主题编辑、单项复原、整体复原及导入，不把分类与搜索计入历史。切换路由保留当前会话，刷新不自动覆盖当前主题；通过“恢复已保存草稿”显式读取此浏览器的草稿。

应用迭鹿预设后重新编辑全局品牌时，仍等于原预设的主色三态、链接、焦点及主按钮填充交还品牌生成器；已改成其他值的单项覆盖、其他语义色与圆角保留。全局编辑器和预览弹窗使用相同入口，支持历史撤销与文件导出。

### CSS 变量与作用域

- `--semi-*` 为当前公开主题/颜色 API 实际支持的变量。
- `--studio-*` 是工作台生成的局部适配变量，用于尚未公开为运行时 token 的间距和组件属性。它们通过目录的明确 `.semi-*` 属性映射生成普通 CSS，**不代表公开组件包新增了 CSS API**。检查器显示其真实影响选择器；没有组件绑定的间距仅用于自定义布局。
- 颜色引用在主题容器重新声明，确保基础 RGB 通道编辑会传递到语义颜色。所有逗号分隔选择器逐项加主题边界，避免影响工作台之外的界面。
- 用户主题作用于整个工作台，包括顶部导航、分类、编辑控件、预览及默认 Portal；不改变 body/html 或文档站主题。顶部图标是唯一全局明暗入口，不再常驻显示浅色对照或局部深色对照。局部主题仅在主动进入局部主题编辑/预览时展示，关闭后恢复外层继承。

主题表单中带链接和关闭操作的气泡使用 Popover，背景及箭头跟随 `--semi-color-bg-3`，文字保留当前主题前景；组件编辑页的普通 Tooltip 保持 Semi 的反色提示行为。自定义 Tooltip 背景时，同一变量同时控制气泡背景和 SVG 箭头颜色，在线预览与 CSS 导出一致。

工作台自有 UI 的字体、字号、字重、行高、圆角、间距与状态阴影也引用同一组主题角色，紧凑文字和布局保留相对尺度。组件按对应角色更新，不强制标题、正文和小号标签相同。显式组件属性与独立局部主题继续优先；信息色、成功色和品牌色仍是不同的语义角色。

生成排版预设默认使用全局变量引用，应用后仍可修改基础字号、行高和字重。版本 1 JSON 中与旧预设完全一致的固定排版字符串会在导入时转换为等价引用；其他手工排版不变。独立前景变量作用于工作台普通文字及对应组件，普通文字、禁用文字与状态文字继续分开。

排版便捷设置保留正文 `14px/20px`、400/600 字重和四级标题 `20px/28px` 默认值。默认使用系统字体；选择迭鹿排版后使用本地打包的字体，中文按来源字体栈回退到系统字体。控件高度与排版独立；组件属性编辑可以显式调整对应尺寸。

### 迭鹿品牌与圆角预设

编辑面板的“应用迭鹿预设”用于对照迁移效果。快照来自迭鹿项目的 `frontend/shared/styles/common.css`、`light.css`、`dark.css`，仅包含三种品牌原色、primary/secondary 明暗色阶及状态、链接/焦点等品牌引用和六项圆角。实心按钮三态按同目录的组件映射保留，尤其深色主色前景与品牌实心填充分开；不调用整盘生成器重算来源色阶。

原色为 `#5B5AF7 / #14D3B6 / #A7E9FF`；圆角为 `4 / 8 / 16 / 24px`、`50%` 与 `9999px`。`--dielu-*` 在变量目录保留来源名称，可继续编辑并随 JSON/CSS 导出。原项目、公共主题包和工作台默认基线均不修改，信息/成功/警告/危险色、背景、排版、阴影与动效不迁移。应用预设合并到当前会话，可整体撤销；其他显式变量与排版编辑继续保留。

### 迭鹿排版与前景迁移

“应用排版与前景”是独立的增量入口：合并两种模式的文字层级、禁用文字、内容描边和输入控件 hover/focus 描边，同时采用来源的 Space Grotesk 与 JetBrains Mono 字体栈及正文/标题尺度。字体固定为 Fontsource 5.3.0，随应用本地打包，OFL 许可保留在 `public/fonts`。中文使用系统回退。

本次适配只绑定 `color`、`border-color` 和 `font-family`，不迁移背景、填充、阴影、光晕、遮罩或渐变，也不覆盖可能被组件用作背景的共享文字/边框变量。私有 `--studio-dielu-*` 可搜索、编辑、撤销及 JSON/CSS 导出；独立局部主题保持自身外观，关闭局部主题后恢复外层继承。应用时不重新应用品牌与圆角预设，现有背景相关编辑保留。

CSS 导出包含字体栈与前景映射；独立消费者若需要相同拉丁字形，仍需自行加载上述两个 Fontsource 包的字体 CSS。JSON 保存字体选择和两种模式的前景覆盖。

该入口还包含来源 `typography.css` 的 14 个完整角色与当前预览组件的文字细节：六级标题、说明/代码/长文、输入尺寸对应的行高、选中选项与表头字重、标签与浮层文字等。全局「字体排版」及预览「文字排版」展示真实角色样本；`--studio-dielu-type-*` 可单独编辑，并通过 `.dielu-type-*` 类在 CSS 消费端使用。文档标题在 `640px` 及以下使用 `24px/32px`，其他窗口使用 `32px/44px`；窄屏角色有独立变量，导出保留媒体查询。

键盘焦点采用来源的 `2px solid` 轮廓与 `2px` 间隔，绘制在 Button、Switch、Checkbox、Radio 的可见外层；后面三类匹配实际原生 input 的 `:focus-visible`，鼠标操作不触发这套轮廓。颜色复用当前模式的焦点色，不增加光晕。字体和轮廓适配排除独立局部边界；现有按钮/选择器公开排版变量与组件单项覆盖继续生效。迁移不修改组件高度、内外边距或图标尺寸，不引入动效和状态配色。

### 阴影与交互适配

“应用阴影与交互”独立合并 `--studio-dielu-effect-*` 覆盖，不重新应用品牌、排版或背景。默认几何来自迭鹿的 `common.css`、`interactions.css`、`light.css` 和 `dark.css`：hover、focus/open 均为 `0 0 0 4px` 单层光晕，不增加模糊或额外外扩。单行输入、Select 与正常 TextArea 使用当前焦点/校验色，浅色显色比例 `10%`、深色 `18%`，hover 与 focus 相同；TextArea 错误/警告分别使用当前 `danger-light-default` / `warning-light-hover` 作为阴影颜色，不写回背景。

Card、Popover 与 Modal 共用来源的 elevated 阴影几何：浅色 `0 0 1px / 0 4px 14px`，黑色透明度分别 `30% / 10%`；深色 `0 8px 28px`、黑色 `40%`，再加外侧 `1px`、当前文字色 `12%` 的边缘阴影。边缘不使用 inset，不自行拆成三档大范围阴影；Tooltip 保留组件原有外观。

新增反馈只绑定 `box-shadow` 和 `transition` / `transition-duration`，不改背景、填充、控件尺寸、位移、缩放或展开行为。控件过渡使用 `150ms ease`，只作用于阴影、描边和文字；`prefers-reduced-motion: reduce` 下时长为 `0ms`。卡片保持组件本来的 `300ms` 阴影过渡。禁用、无边框及组合选择器内部搜索不增加光晕，只读输入与来源一样保留反馈；独立局部主题保持原样。预览「阴影与交互」可检查 Input/TextArea/Select 状态、悬浮卡片及默认弹层；覆盖支持编辑、撤销和 JSON/CSS 导出，已有背景相关编辑继续保留。

### 本地保存与文件

“保存草稿”只写此浏览器的 `theme-studio-draft-v1` 键；草稿读取和文件导入均经过同一校验。输入无效值、未知变量、变量循环或不完整文件时，保留现有合法主题并显示错误。主题不上传任何服务。

JSON 文件包含全局、局部、组件设置及两种模式的覆盖，可完整恢复编辑会话。CSS 文件包含全局深浅模式与组件适配规则，加载公开默认主题 CSS 后，在消费容器设置 `class="theme-studio-theme"` 以及 `theme-mode="light"` 或 `theme-mode="dark"`。局部主题配置作为独立预览对照保留在 JSON 中；CSS 导出应用当前全局设计。两种格式都通过浏览器下载，不构建或发布 npm 包。

### 参考与验证

已通过 Chrome 检查 [Semi DSM](https://semi.design/dsm/web_console/tokens?dsmID=31334) 的全局样式、组件样式、预览场景及交付入口。线上发布窗口显示 Semi `2.104.0`，本地行为及默认变量继续以仓库固定 `2.102.0` 为准；例如本地公共动效时长/延迟默认值为 `0ms`，不会套用线上项目的 180/600/1800ms 设置。主题包发布、发布版本回滚及云端成员协作不在本工具范围。

`playwright.theme-studio.config.ts` 使用完整 Chromium 新 headless、3 workers、0 retries。正式测试覆盖品牌与默认色差异、输入反馈、ColorPicker、排版、组件覆盖、局部隔离/继承、默认弹层打开中更新与清理、变量引用联动、模式独立编辑、历史、本地草稿、文件导入导出，以及 390、768、1024、1440 四档实际页面布局。截图与报告放入已忽略的 `test-results` / `playwright-report`。

浮层定向检查见 `tests/theme-studio/overlays.spec.ts`：覆盖各类下拉、两个颜色面板及其格式菜单、三处 Modal 和独立局部气泡；保持浮层打开，在同一 Portal 上切换浅→深→浅，检查实际背景与文字。Tooltip / Popover 另外检查箭头，局部主题检查隔离及撤回后的继承。

全界面联动检查见 `tests/theme-studio/interface-style.spec.ts`：覆盖默认/预设两种起点、排版、颜色状态、圆角、间距、阴影、组件覆盖优先级，以及旧文件中默认与手工排版的区别。

交互状态检查见 `tests/theme-studio/component-states.spec.ts`：默认/完整预设下保持同一组件实例，反复更新浅→深→浅及状态变量，检查按钮悬浮/按下、输入悬浮/聚焦、复选/单选/开关选中与键盘轮廓、禁用控件及选项、表格悬浮与选择。禁用样本仍阻止操作；保持键盘焦点时更新主题不丢失焦点。默认输入的悬浮填充、透明描边与预设描边分别遵循各自规则。
