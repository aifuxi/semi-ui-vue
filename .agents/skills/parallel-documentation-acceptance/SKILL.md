# 并行文档严格验收

从[批次计划](../../../docs/documentation/batch-plan.md)、覆盖账本和所选批次材料确认当前状态，按用户范围完成一轮。验收标准与命令见[文档工作流](../../../docs/documentation/workflow.md)，无需加载无关组件的历史记录。

- 按共享依赖和交互复杂度划分独立任务，遵守用户并发上限。每个子任务明确目标、可写路径与完成条件；共享文件只有一个写入负责人。
- 子 agent 准备参考适配、示例、矩阵和审阅，交付改动、验证结果及未解决问题。主 agent 整合共享修复、账本和最终证据；根据瓶颈调整分工。
- 共享构建、浏览器服务和证据写入由主 agent 调度。运行前稳定受追踪输入，运行期间避免其它任务修改这些输入或产物。
- 正式验收前完成语义审阅、低成本检查、适用的代表诊断和 `--preflight`；按实际矩阵及资源容量组织运行。失败先用完整复现路径定位，修复后重验失效范围。
- `--affected --plan` 用于识别影响和复用有效证据。一轮新批次验收不自动承担全部历史证据恢复；受影响历史批次如实保留失效状态，仅在目标要求恢复时运行其完整矩阵。必要的组件修复与回归仍按实际影响完成。

完成范围以有效正式证据为准；未通过项保留 pending 和具体原因。更新所选批次记录、覆盖账本与队列，按根规则提交已完成修改。交付说明新增进度、实际验证、历史失效或重验范围、剩余问题与提交号，不要求另建报告或手工逐阶段计时。
