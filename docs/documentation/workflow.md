# 示例补齐与严格视觉验收

本流程用于后续所有文档示例补齐、已有示例修复和视觉验收。视觉、行为和发布标准继续遵守根目录 `AGENTS.md`；根据实际改动选择验证范围，不把每次示例维护重新当成组件从零实现。

## 双线完成标准

两条线独立选批、交付和报告，复用现有映射与证据体系，不要求补齐批次同时通过严格矩阵。具体队列见 [双线计划](./batch-plan.md)。

| 工作线             | 完成标准                                                                                                                                                         | 统计与边界                                                            |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 双语示例补齐       | 固定上游的中英文示例、章节关联、语言差异说明及多文件依赖齐全；映射、内容和类型检查通过；本批每个双语示例在实际文档站加载运行并验证主要演示操作，无阻断运行的错误 | 更新映射并报告运行证据；不生成 `accepted`，不承诺精细视觉与行为一致   |
| 严格视觉与行为验收 | 已补齐示例与固定 React 基线完成双语、明暗及适用 RTL/交互矩阵，样式、几何、截图和行为满足门禁；章节/API/迁移审阅有效；正式证据有效                                | 只有完整正式验收可计入 `accepted`，诊断、映射或基础运行检查均不能替代 |

账本中的已映射数量不用于追认全部示例已通过统一运行检查。基础加载、编译和运行错误属于补齐线必须修复的问题；已识别但不阻断演示的精细对齐差异记录到现有批次材料或工作记录，交给验收线处理，不算 accepted deviation。最终完成标准不变。

## 补齐线流程

1. 按队列列出固定上游索引、双语顺序/独有差异和多文件依赖，核验 Git 状态、vendor 基线及路径大小写。先选本批最简单和最高风险的代表示例，写下名称、触发条件和关键断言；记录在现有映射或工作记录中，不另建一套清单。
2. 先只实现代表示例的中英文版本，执行本批文件的 lint、内容注册及适用的低成本类型检查。在首次完整静态构建之前发现导入、模板回调返回类型、locale 数据和资源依赖问题；已有准备产物才可直接使用不重复准备的检查命令，缺失或过期时先补齐对应资源。此时不得预先生成、复制或批量修改其余示例及对应文档注册。
3. 在实际开发站或已准备的静态站验证双语代表路径，按下节完成运行预检。任一代表失败时停止扩展，保留真实触发条件、定点修复并重跑该语言和阶段；只有双语代表浏览器路径实际通过后才进入第 4 步。代表通过不等于本批全部通过，也不生成 accepted。
4. 补齐其余示例与映射，逐项检查本批中英文示例的加载和主要操作，以及适用的源码、重置、编辑器或多文件运行路径。发现问题回到对应定点检查，不把每次修复都升级为联合构建或全矩阵。
5. 相关修复稳定后集中执行 `check`，对最终静态产物完成本批逐项运行检查。若改动组件或共享设施，同阶段集中跑真实依赖的回归和必要发布包验证；检查历史证据失效范围，按验收线重验失效批次。不能为维持计数修改指纹或沿用旧证据。
6. 最后刷新覆盖账本、保存运行证据与已知非阻断差异，记录下一批。仅补齐示例不要求创建严格验收 spec；映射进度与有效严格验收进度分别报告。代码或依赖再次变化时只重跑失效范围，不能以“只构建一次”为由使用旧产物。

## 补齐线运行预检与失败定位

代表用例按风险选，不按上游顺序只检查前几个。通常先选一个基本示例和一个覆盖最多关键状态转换的示例；同一示例已覆盖多个风险时不要重复增加用例。没有浮层、异步或编辑器路径的示例不强行套用对应检查。

| 风险              | 首轮就要验证的可观察结果                                                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 双语与 Provider   | 最简单示例的中英文均打开运行；同时检查内置按钮/提示和用户提供文本。读取当前组件的 locale 消费逻辑，不能从上一组件推断只传 `code` 就会加载完整语言数据。  |
| Portal 与生命周期 | 首次打开→输入/选择→提交或取消→退出动画结束→重开后还能操作；SSR 页面保留真实 hydration 条件。不能用 `motion=false`、强制重建 key 或仅首次挂载代替该路径。 |
| 受控/异步内容切换 | 覆盖空值/非空值、缺省/显式空值/移除覆盖、提交→完成提示→自动关闭等适用转换；不能把 prop 是否传入等同于 truthiness。                                       |
| 编辑器与资产      | 最简单与依赖最复杂的示例先验证源码、编辑运行及其依赖；字体、图片、Locale 和多文件路径均需实际可加载。                                                    |

### 写烟测前先观察

- 用交互浏览器观察真实 DOM、ARIA 和可点击区域，再把操作写成 Node + 仓库锁定 `@playwright/test` 的短 smoke。临时脚本复用 `.agents/skills/ai-change-workflow/scripts/documentation-smoke.mjs` 统一创建浏览器/context、采集错误、记录具名阶段计时和关闭动效项；不得在每批复制一套 runner。浏览器工具用于观察/截图，批量 matcher 不放进 Bun Eval，也不为测试反复叠加 CDP 连接与默认 context。
- 外层 class 不等于可见裁剪容器：先确认 bounding rect，再选择实际浮层。按钮的可访问名称可能来自 `aria-label` 而非显示文案；样式化 input 可能被展示层覆盖，应操作真实可点击文本/控件。不要靠猜标签名、`force: true` 或扩大超时掩盖定位错误。
- iframe 操作前同时检查主页面中的 iframe 与 iframe 内部控件是否进入视口；先滚动正确层级，再操作，不把坐标错误当成组件故障。
- 首个代表 smoke 跑通后再扩展循环；用具名阶段和通常 5–10 秒的局部有界断言，让失败停在具体条件。相互隔离的中英文 context 默认并发运行；存在明确共享状态或资源约束时才串行并记录原因。编译、加载或公开异步契约确需更长等待时单独说明，不让每个错误定位器耗尽全局长超时。
- 错误先分为示例接入、组件缺陷、定位/时钟/测试环境问题，再改对应层。共享 runner 只把精确匹配的 Volar 浏览器提示，以及开发站中同一编辑器阶段已出现固定 worker 请求失败时的关联错误列为 `knownIssues`；静态站不允许开发 worker fallback。不得统一忽略 console error。整批 smoke 失败后先根据摘要定点重跑失败语言和具名阶段，稳定后再回到整批。

### 保留真实时序，隔离编辑器

- 复现须保留浏览器里的完整状态转换。初始探针不复现时，优先对照是否省掉 SSR、退出态渲染、动画结束或再次挂载；不能不断换环境却重复同一个不完整探针。
- 类型/单元检查使用可控时间或公开事件；真实焦点、Teleport、动效和几何仍须 Chromium 验证。不要用固定 sleep 猜测状态已经完成。
- 含 Monaco/REPL 的完整编辑运行使用真实时钟。需要验证定时边界或截取短暂完成提示时，另开不加载编辑器的独立页面/context，只在那里控制时钟；不要在加载过编辑器的页面暂停/快进时间后继续验证编辑器。
- 短暂状态截图前先完成字体/图片准备，再触发该状态；必要时在隔离页面控制采样时刻，不能延长组件业务定时器或关闭被验收的动效。

### 分阶段使用验证入口

| 阶段           | 运行范围                                                             | 不应提前做的事                                                   |
| -------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 代表实现与定位 | 本批文件静态检查、实际开发站代表路径、真实失败条件的定点回归         | 为修定位器或补一个 prop 反复生成静态站、安装 tarball、跑整套矩阵 |
| 本批扩展       | 逐项双语运行与适用编辑器路径；失败时只回到对应场景                   | 用部分成功替代全批完成，或把补齐线升级为全量严格验收             |
| 修复稳定       | 联合检查、最终静态站逐项运行、受影响组件与消费者回归、必要真实包验证 | 在源码仍修改时并行共享构建或运行正式验收                         |
| 证据与交付     | 代表矩阵→受影响正式矩阵→一次刷新账本与归档；有效批次跳过             | 为提交重复未失效检查，或只因数量不变就沿用旧证据                 |

开发站 HMR 只能用于预诊断：修改组件、主题或 REPL 依赖时须更新对应公开包/资源，不能拿旧 dist 的结果验证新源码。最终交付仍以联合检查后的静态产物为准。每次重跑已通过的重验证，先指出导致失效的源码、依赖、产物变化或前次失败；只有临时 smoke/定位器变化且准备产物仍有效时，不重建站点。

开发站、静态预览和正式验收服务分阶段使用；切换前停止前一服务并释放端口。不得一边做浏览器采样，一边重建它正在消费的公开包、主题或 REPL 资源。

## 验收线流程

1. 从已补齐队列独立选择当前批次，无需等待所有示例补齐。检查 Git 状态、vendor 基线、映射和实际运行情况；已有对齐矩阵按差异更新，不重复建立整套材料。
2. 在编写交互断言前，先确认 React 参考侧能独立运行，并核对原站 Provider、语言、主题、Portal 容器和键盘/hover 契约。先区分参考环境缺失、采样误差与真实组件差异，再修复示例及必要的组件差异。用户已授权的范围内直接推进；发现无关问题记录后继续当前目标，不自动扩展下一组件。
3. 先执行当前批次的自动代表用例：全部示例的双语首主题，再加暗色与各方向敏感示例 RTL；需要定位已知失败时用 --grep 精确选择。通过新鲜度校验复用准备产物，变化或缺失才自动重建。代表用例按结构/默认视觉、主题、浮层、键盘分阶段诊断，使用具名 `test.step` 和局部有界断言；不要让错误状态耗尽整个用例的长超时。代表用例通过后再跑完整双语、明暗、适用 RTL/交互矩阵。诊断用 `--grep` 结果不能计入 accepted。
4. 修复稳定后集中运行受影响的组件回归、类型和真实包验证；修复期间优先定点测试，不在每个中间版本反复做完整发布包验证。只有共享基础设施、主题、运行时影响范围要求时才扩大回归；通过的检查不因“准备提交”而重跑。
5. 最后使用正式入口一次验收当前批次及受影响历史批次。运行期间冻结本轮受追踪的源码输入和准备产物，不一边修改相关文件一边跑验收；补齐线可处理无关输入，但共享修改与构建须错开，不得覆盖本轮产物。证据有效的批次直接跳过。失败时先诊断实际失败用例，不立即重复整套长耗时门禁。
6. 检查最终 diff 和证据状态，报告完成范围、必要验证及剩余问题。用户要求提交时只提交相关文件，已验证且未变化的源码不再触发构建。

## 命令入口

### 补齐线

```bash
# 代表阶段：只校验/重建 resources，再更新内容注册与覆盖数据并启动开发站
# 保持同一进程；不会提前执行静态站生成、全量检查或严格浏览器矩阵
node .agents/skills/ai-change-workflow/scripts/documentation-dev.mjs

# 只验证开发准备缓存与内容生成，不启动服务；计时写入 ignored 的 development/latest.json
node .agents/skills/ai-change-workflow/scripts/documentation-dev.mjs --prepare-only

# 仅在已有对应公开包、REPL 资源及 Nuxt 准备产物时：
# 更新内容注册并检查，再直接做类型检查；不代替最终联合门禁
pnpm --filter @workspace/docs check:content
pnpm --filter @workspace/docs exec nuxt typecheck

# 修复稳定后的联合构建、类型、内容与产物检查；不执行严格浏览器矩阵
pnpm --filter @workspace/docs check

# 刷新映射和当前有效验收计数；不要求全量验收完成
node apps/docs/scripts/prepare-coverage.mjs

# 启动实际站点后检查本批双语示例；命令本身不证明运行检查完成
pnpm --filter @workspace/docs preview
```

补齐线不使用 `check:nuxt:coverage` 或 `prepare-coverage.mjs --batch=<批次>` 作为完成门禁：前者要求全量严格验收，后者要求对应批次已有有效严格证据。基础运行检查不能由覆盖生成器代替。

### 验收线及共享影响检查

```bash
# 开始前查看失效范围，同时检查映射路径的精确大小写；不构建、不跑浏览器
pnpm --filter @workspace/docs accept:nuxt:batch --affected --plan

# 默认代表用例：自动校验/复用构建，不生成 accepted
pnpm --filter @workspace/docs diagnose:nuxt:batch navigation

# 定点诊断：仅跑失败用例，测试改动不重建站点
pnpm --filter @workspace/docs diagnose:nuxt:batch navigation --grep 'Template zh-cn light$'

# 查看诊断范围；或仅准备并检查可复用产物
pnpm --filter @workspace/docs diagnose:nuxt:batch navigation --plan
pnpm --filter @workspace/docs diagnose:nuxt:batch navigation --prepare-only

# 单批正式验收，或多个批次共用一次构建
pnpm --filter @workspace/docs accept:nuxt:batch button
pnpm --filter @workspace/docs accept:nuxt:batch button icon

# 当前批次加上证据失效的历史批次，稳定后一次刷新
pnpm --filter @workspace/docs accept:nuxt:batch locale --affected
```

修改用例选择逻辑时，同时检查逻辑计划与 Playwright `--list` 实际发现的完整集合；`--plan` 有标题不代表 runner 能匹配到它们。Playwright 的 grep 输入包含项目、文件和分组前缀，表达式须保留精确用例后缀及必要边界。零用例始终是失败，不能用来声称验证通过。

正式与诊断入口共用三阶段准备：resources 构建公开包/主题及本地资源，site 生成 Nuxt 静态站点，checks 执行类型/内容/产物检查。每阶段按输入内容、前置产物摘要、Node/平台/构建环境及安装锁记录缓存；所有产物文件及完整文件集合均按内容哈希校验。源码变化、缺失/新增/篡改产物、上次失败或运行中变化会自动失效，没有手工跳过构建的选项。文档改动复用 resources；纯测试改动复用 resources/site，仍运行实际消费测试文件的 Nuxt typecheck。独立 `build`、`typecheck` 保留原有自行准备语义；日常示例修复优先使用统一诊断入口。

完整矩阵仍在一次 Playwright 调用内共享服务；每个用例独立 context、同 worker Chromium 中配对 React/Vue。默认 3 workers 并行用例，保持各用例内部交互顺序；可用正整数 `DOCS_PARITY_WORKERS` 显式调节。并发改变不允许减少断言或靠重试消化失败。无失效批次不启动构建或浏览器。诊断默认 retries=0、max-failures=1，结果只用于定位；正式仍要求全部选定矩阵一次通过。

REPL 资产入口按固定小组共享打包，根入口与公开子路径使用同一份组件实现，UI 保留按需拆分，Vue 和跨包资产通过统一 import map 加载。生成时验证每个公开入口的传递静态模块请求数不超过 200；不得通过为每个入口重复打包运行时或让简单示例加载全库来降低表面请求数。

准备记录位于 ignored 的 `apps/docs/.data/documentation-preparation`；验收持有本轮输入/产物证明，浏览器结束后重新核验，不能被其它构建后来写入的缓存记录替代。清理构建后自动恢复，不要求使用者管理缓存键。

成功与失败运行均输出 `apps/docs/test-results/acceptance-timing.json`，记录各构建/检查/浏览器阶段、总耗时和最慢的十次用例执行（含 retry/status），并保留 worker 数、用例数量/集合哈希与原始浏览器 stats。准备缓存命中、失效原因和校验耗时也记录在 stages。诊断对应 `diagnostic-timing.json`，不会覆盖正式计时。共享原始报告为 `test-results/batches.json`；持久证据仍逐批保存，批次 `stats.duration` 为该批测试执行时长之和，整轮墙钟时间保留在 `sharedRunStats`，不能把整轮时间重复归给每个批次。

## 烟测证据保留与清理

- 本批短 smoke 的脚本、JSON 摘要和局部截图统一放在 ignored 的 `apps/docs/.data/documentation-smoke/<批次>/<运行标识>/`。不要放在 Playwright 默认 `test-results` 内或正式/诊断入口的输出子目录内；Playwright 启动时可能清空指定输出目录。
- 直接运行 Playwright 时显式使用独立 `--output`，例如在 `apps/docs` 下指定 `--output=test-results/manual-diagnostic`；JSON reporter 路径也不能覆盖 smoke 或正式 evidence。正式入口继续使用既有目录，不为保存烟测结果改变其指纹或报告约定。
- 清理临时脚本前，先保存覆盖的完整用例清单、浏览器构建/viewport/DPR/locale/主题、关键操作结果、错误分类和必要截图。失败输出与最终通过输出分开，记录不得把早期失败目录称为最终证据。
- `.data` 不受普通 Playwright 输出清理影响，但仍会被项目 `clean` 删除。运行 clean 或其它清理前，先把需要持久保留的结果转入本批约定的归档位置，并在现有工作记录中保存关键事实及实际保留路径；不能仅引用即将删除或已经不存在的文件。
- 基础 smoke 仍不是 accepted。正式证据只由完整验收入口生成；本节不新增验收状态、永久 smoke 测试框架或重复报告系统。

## 影响范围与证据

批次声明 `dependencyMode: imports-v2`：从当前 Demo 和文档外壳的脚本导入出发，追踪 UI 公开子路径、相对导入与再导出。共享 Tooltip 等组件仍会使真实消费者失效；无关 Demo、无关 UI 组件及 React 普通场景不会触发重验。UI 纯类型导入不作为视觉依赖，类型检查仍在正式验收中执行；公共 API 变更另按组件门禁验证。

批次 `inputs` 必须保留实际使用的内容、API 元数据、资产、主题、Foundation、包导出/构建配置、锁文件、React 文档编译器、文档外壳和浏览器 fixture。图标与主题保守按包追踪；Foundation 按实际命名导出追踪纯转发模块，共享运行时工具/构建配置仍追踪。转发目标缺失、含副作用、样式或越界时保守扩大。动态 import、未知别名、无法解析的本地依赖会扩大到全部 UI，并在计划中说明；不能手工删依赖来让证据继续有效。新增非 UI 共享依赖时同步补充 `inputs`。

`DemoBlock` 与 `ApiTable` 的固定页面注册表按本批目录/API 选择输入；修改注册表实现本身仍会使所有使用批次失效。更改指纹算法须重新生成浏览器报告，禁止把旧报告直接改成新指纹。共享报告按明确的 spec 归属拆分；未知 spec、重复认领、任一批次缺项/失败/重试/跳过或全局错误均拒绝整轮。完整矩阵全部通过、无重试/跳过且运行前后源码一致后，才统一写证据并刷新一次覆盖统计。

## 确定性视觉上下文

复用 `apps/docs/tests/nuxt/visual-context.ts` 的同进程 Chromium context 和 `waitForVisualAssets`，在截图前真实加载 Inter 字体、解码目标内图片；缺失资源直接失败。参考与 Vue 均使用静态站点本地资源，预览脚本提供字体/REPL 所需 CORS。

继续使用 `demo-parity.ts` 的 `freezeAnimations`，按上游状态显式选择动画采样时间，不能一律跳到动画结尾。截图前对齐裁剪范围、文档滚动和坐标，默认态将指针移到空白区；需要 hover/focus 的用例显式进入对应状态。交互导致滚动后重新对齐，不用延长固定 sleep 掩盖时序问题。

验收仍要求关键 computed style 精确相等、各轴几何差不超过 0.5 CSS px、截图 threshold ≤ 0.1、差异比例 ≤ 0.001；可见局部差异仍须解释并修复或按源码证据记录 deviation。不得扩大裁剪、mask、容差或盲目更新基线提速。

## 避免不必要的共享改动

新增批次的参考编译适配、品牌替换和站点交互放入 `apps/reference-react/docs-adapters/<batch>.mjs`；共享插件自动发现惰性入口，批次仅追踪自己的适配器及递归依赖，新增适配器不会改变其它批次的输入。接入前查看 `--affected --plan`。共享入口确需改变时仍重验全部真实消费者，不靠删除 inputs 或改写旧指纹保留 accepted。可复用的裁剪、字体、滚动及动画确定性问题先在代表场景解决，再铺开场景矩阵；不能让每个主题/语言重复承担同一轮工具排错。

修复验收脚本前也须检查批次 `inputs`。当前批次将整个 `apps/docs/scripts` 纳入指纹，修改诊断选择或其测试也会使这些批次的历史证据失效；先明确影响，再定点验证稳定，最后统一重验。不要因“只是脚本”沿用旧证据，也不要为避免重验删除输入或改写旧指纹。
