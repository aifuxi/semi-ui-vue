# 组件示例复杂度梯次

本文用于确定当前 VitePress 文档站的组件示例迁移顺序，并同步记录各批次完成状态。

## 基线与统计口径

- 唯一代码基线：`vendor/semi-design` 的 `v2.102.0` / `cdfba6e520fc83ad871b30f51f36d8af3aaa5a21`。
- 示例来源：`vendor/semi-design/content/<route>/index.md`，以页面中的代码块顺序、数据、文案、属性、交互和布局为准；React 写法按项目 Vue 契约转换，不逐字照搬 React API。
- 当前范围：`apps/docs` 已收录且存在 Vue 实现的 82 个组件页面。
- 当前状态：82 个组件页共 1,033 个 `DemoBlock`，其中 855 个可运行示例、72 个引入示例和 106 个静态代码示例均已完成。
- 下文数量仅统计 855 个可运行示例。引入示例复用公共 code-only 展示链路，不运行预览；静态代码示例不参与组件难度排序。
- 组件按页面中最复杂的示例定档。同一组件内仍按“静态展示 → 本地状态 → 组合/浮层 → 异步/浏览器能力”由易到难迁移。

## 分级标准

| 梯次          | 主要特征                                                       | 典型 Vue 转换                                              | 主要验收风险                     |
| ------------- | -------------------------------------------------------------- | ---------------------------------------------------------- | -------------------------------- |
| T1 静态展示   | 单组件或纯布局；以 props、样式、普通 slots 为主                | JSX 转模板、`className` 转 `class`、图标转 slot            | DOM、样式和响应式布局            |
| T2 基础交互   | 本地状态、受控值、普通事件；无复杂浮层或环境依赖               | `useState` 转 `ref` / `reactive`，事件转 emits / `v-model` | 默认值、受控切换、事件顺序       |
| T3 组合交互   | Portal、命令式调用、Provider、复杂 slots、日期时间或多组件联动 | scoped slots、`expose` / composable、可见性状态            | 浮层定位、焦点、键盘、卸载清理   |
| T4 环境与数据 | 异步、文件/媒体、拖拽缩放、虚拟化、树形或大数据                | 浏览器 API、异步状态、递归数据、拖拽事件                   | 客户端边界、资源稳定性、复杂交互 |
| T5 系统级示例 | 多子系统组合、长链路状态、复杂数据模型或超长示例               | 多组件协作、流式/异步流程、复合表单与表格                  | 契约覆盖面、示例隔离、回归成本   |

示例行数和数量只用于估算工作量，不单独决定复杂度；一个示例很多但纯静态的组件，不因此升到 T4/T5。

## 建议实施顺序

1. ✅ 已完成最小公共链路：`DemoBlock` 能按 `id` 载入 manifest、展示源码并运行一个 Vue SFC；首个示例为 `Divider / 基本用法`，未加入批次系统或新的验收平台。
2. ✅ 已完成 T1：15 个组件的 83 个可运行示例按稳定 ID 登记，并复用此前按固定基线验收的 Vue SFC。
3. ✅ 已完成 T2：24 个组件的 228 个可运行示例按稳定 ID 登记，并修复验收中发现的 SSR hydration 差异。
4. ✅ 已完成 T3：22 个组件的 184 个可运行示例按稳定 ID 登记，补齐实验图标包与动画资源，并修复示例暴露的 SSR hydration 差异。
5. ✅ 已完成 T4：15 个组件的 238 个可运行示例按稳定 ID 登记，补齐图片、音频与视频资源，并复用浏览器 API、拖拽、虚拟化和异步示例。
6. ✅ 已完成 T5：6 个组件的 122 个可运行示例按稳定 ID 登记，覆盖复合表单、表格、消息流、结构化输入和多区域组合场景。
7. ✅ 已完成 72 个引入示例：内容生成时保留经包名改写的源码，由 `DemoBlock` 直接展示，不创建或运行 Vue SFC；Table 上游误标为 `import` 的完整 React 示例仅保留导入语句，基础用法由紧邻的可运行 Vue 示例覆盖。
8. ✅ 已完成 106 个普通静态代码示例：复用同一 code-only 链路并规范化语言标识；React 类型名通过公共 Vue 契约表改写，无法安全机械转换的 JSX 按稳定 ID 提供 Vue 版本。
9. 82 个组件页的 1,033 个示例均已完成；后续新增或变更示例时，继续保持上游数据、文案、属性、交互和布局，仅做必要的 React → Vue 契约适配，并记录无法等价的差异。通用指南页的 15 个代码块不计入该组件示例清单。
10. 每个梯次完成后再进入下一梯次：先定向运行受影响组件的 hydration 单测，再以 `DOCS_EXAMPLE_TIER=tN pnpm test:docs` 做一次生产构建与全部页面聚合巡检；涉及 Portal、拖拽、媒体或虚拟化时增加对应关键交互和浏览器检查。
11. 生产巡检出现笼统 hydration 警告时，叠加 `DOCS_HYDRATION_DIAGNOSTICS=1` 获取节点差异；修复期间不反复做全量公开包构建，仅 UI/主题变化使用 `pnpm docs:prepare:ui`，资源包变化才重新执行 `pnpm docs:prepare`。

## 本轮评审重点

- 是否接受以“组件内最复杂示例”作为组件梯次，而不是把同一组件拆散到多个批次。
- 是否先以 855 个可运行示例为主线，72 个引入示例和 106 个静态代码示例随公共代码展示能力一次恢复。
- T3/T4 的边界是否符合预期，尤其是日期类、媒体类和数据选择类组件。
