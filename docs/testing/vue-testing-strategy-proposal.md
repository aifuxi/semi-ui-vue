# Vue 测试体系替代方案

状态：目标方向已确定，Vitest/Storybook 的完整迁移仍待实施，2026-09-13。Nuxt 文档站与旧逐示例验收已先行移除；本次调整 Chromium 模式并接入 Playwright CLI/skill，Vitest/Storybook 与 CI 工作流调用尚未切换。组件库尚未正式发布，用户已明确允许修改或删除现有内容。后续实施以目标体系为准，旧实现、工具、命令、配置、测试组织和验收协议均可重写、替换或删除，无需维持旧内部体系的兼容性。

## 建议与依据

目标栈为 **Vitest + Vue Test Utils + jsdom / Node，Storybook Vue 3 + Vite，Playwright Test**。对齐 Semi 的测试分层和公开行为，用 Vue 原生工具替换 React 的 Jest/Enzyme 用法；减少重复状态验证与自建验收调度。相关组件实现和构建链均可按目标需要修改或替换；是否复用只看实际价值和维护成本，不以“已经存在”或历史投入为保留理由。

Vue 官方推荐 Vitest 和 Vue Test Utils；Element Plus、Naive UI 当前官方仓库也采用这一组合，并将 SSR、文档类型或产物检查另设入口。这是生态成熟度依据，不代表它们的行为可以替代 Semi 基线，也不代表 Vitest 在本仓库一定更快。[Vue 测试指南](https://vuejs.org/guide/scaling-up/testing.html)、[Element Plus 配置](https://github.com/element-plus/element-plus/blob/dev/vitest.config.mts)、[Naive UI 配置](https://github.com/tusen-ai/naive-ui/blob/main/vite.config.mts)。

本仓库已有 Vue Test Utils；需要替换的是 Rstest runner/API 和相应配置。历史同环境单次记录为 Vitest 51.67 秒、Rstest 35.1 秒，且 Rstest 有 Vue 覆盖率补丁。因此采用 Vitest 的理由是生态集成、配置和维护成本，不能宣称 runner 替换会提速。[迁移记录](../../ai-work/20260910-103000-rstack-migration.md#第四阶段单测迁移到-rstest)。

Storybook 提供正式的 Vue 3 + Vite 集成。它在本方案中负责场景组织和调试，浏览器断言统一由现有 Playwright Test 承担；暂不同时加入 Storybook test-runner、Cypress 或 addon-vitest。后者官方支持 Vue/Vite，但现在接入会增加另一套浏览器执行入口，收益尚未验证。[Vue 集成](https://storybook.js.org/docs/get-started/frameworks/vue3-vite)、[Vitest addon](https://storybook.js.org/docs/writing-tests/integrations/vitest-addon)。

版本在实施时核对 Vue、Node、Vite、插件的 peer 范围并锁定稳定补丁版；不直接照搬生态仓库版本，不依赖预览版功能。现有 Playwright 常规页面测试足够承载方案，不需要引入新的组件挂载运行时。

## 已确定的本地执行方式

目标体系的组件测试仅在本地运行。本地保留 Playwright 自动测试，默认 3 workers；浏览器采用完整 Chromium 的新 headless 模式（`channel: 'chromium'`、`headless: true`）。需要观察页面或定位问题时，通过 `--headed` 临时开启窗口。

本次复用已锁定的 `@playwright/test@1.62.1`，增加 `pnpm playwright:cli`，并通过官方 `install --skills=agents` 安装匹配的项目 skill。CLI 的 `.playwright/cli.config.json` 同样默认完整 Chromium 新 headless，用于本地页面操作与诊断；自动回归由 Playwright Test 承担。命令见[工具链](../architecture/toolchain.md#本地-playwright)。这部分接入不代表完整测试体系迁移或组件验收已完成。

## 每一层只承担明确的责任

| 层次                | 推荐工具与载体                                          | 核心职责                                                             | 与固定 Semi 的关系                                   |
| ------------------- | ------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------- |
| 源码与类型          | TypeScript、vue-tsc、现有 ESLint                        | 公开 props/emits/slots 类型、exports、源码质量                       | 将 React 专属 API 映射为 Vue 契约                    |
| 单测与 DOM 组件测试 | Vitest + Vue Test Utils；默认 jsdom，SSR 使用 Node      | props、emits、slots、v-model、受控更新、事件顺序、异步完成和卸载清理 | 迁移上游行为用例的输入与预期，不照抄 Enzyme 调用     |
| 组件浏览器对照      | Storybook Vue 场景 + Playwright；React 保留固定参考应用 | 真实焦点、Portal、几何、主题、RTL、拖拽、滚动、动效、关键像素        | 同环境运行真实 React/Vue，用相同输入和可观察结果核对 |
| 静态组件文档        | 仓库 Markdown 与公开类型                                | API、使用与迁移说明的准确性；代码片段按实际契约核对                  | 保留固定源码依据，不要求恢复旧站点逐示例矩阵         |
| 发布消费            | 现有 SSR、主题、tarball、隔离安装脚本                   | 无 DOM 导入、实际 exports/CSS、Vue 消费、发布包完整性                | 验证 Vue 包交付契约，不用源码单测代替                |

普通逻辑在单测层系统覆盖；真实浏览器独有风险必须在浏览器验证。一个交互链有明确的主要测试位置，只有不同入口确实带来独立故障面时才重复深测。jsdom 的通过不能证明布局正确，场景页面能加载也不能证明交互正确。

## 如何替换当前体系

| 当前部分                                    | 目标处理                                                                                                |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Rstest 单测与覆盖率配置                     | 按公开契约迁移或重写有价值的测试；删除重复及依赖废弃实现的用例，移除旧 runner、配置与补丁，不保留兼容层 |
| 自建 Vue 对照工作台                         | 由 Storybook stories 替代；有价值场景可复用，其余重写，相关调用方与旧工作台在同一迁移范围内修改或删除   |
| 固定 React 参考应用                         | 保留运行真实 vendor 的能力；现有应用与构建包装可简化或替换，不要求保留旧应用架构                        |
| 组件浏览器测试中的重复交互遍历              | 按公开契约合并，复用场景与必要 helper；真实布局、焦点、Portal 等风险仍由浏览器验证                      |
| 自建正式/诊断浏览器调度                     | 使用 Playwright projects、用例筛选、fixtures、webServer 和标准 reporter；必要基线核验保留               |
| 大量内联附件和分片认证报告                  | 使用标准 reporter，运行产物放本地已忽略目录；保留必要对照图片和失败诊断，不默认内联所有节点的完整样式   |
| Nuxt 文档站与旧文档验收                     | 已移除；历史可从 Git 追溯，不建立兼容包装、恢复任务或替代站点                                           |
| Rslib/Rsbuild 产物构建、Foundation 集成实现 | 按实际价值决定复用、修改或替换；保留公开交付契约，不保留妨碍目标体系的内部耦合                          |

共享构建准备、资源生成、来源核验及其调用方都可以整体重写或删除。核对调用方是为了找齐需要同步修改的地方，避免新构建留下悬空调用，不是保留旧模块的条件。迁移以完整能力为单位：采用标准工具承接仍需要的职责，移除不再需要的职责，并直接更新构建、文档和本地测试入口；无需保留旧命令、目录结构或兼容包装。

Storybook 场景按公开契约组织；有价值的现有组件场景可复用，复杂场景按需重写，不要求从已删除的文档 Demo 恢复。React/Vue 共享场景 ID、数据和结果语义，分别保留框架原生的渲染与事件适配；现有场景注册表和挂载协议均可替换。

## 固定基线与质量边界

唯一行为基线仍为只读 `vendor/semi-design`：`v2.102.0 / cdfba6e520fc83ad871b30f51f36d8af3aaa5a21`。Vue 生态资料仅用于工具选择。上游测试、Adapter、Foundation、样式和文档共同定义契约；上游没有测试的公开行为不能因此被豁免。

每个对照场景保留固定源码依据，核验 React 确实运行 vendor、Vue 确实运行公开组件；来源核验器及元数据格式可以重写，不要求兼容旧格式。不以版本文字、镜像 DOM 或历史图片代替基线。Playwright 负责运行与采集，项目只保留薄的差异比较适配层；没有现成工具能自动证明 React 与 Vue 全量等价。

视觉采样、几何/像素门槛和快照组织也可以重新设计，目标是可靠识别与固定 Semi 的实际可见差异。旧数值和快照只作校准参考，不构成内部兼容义务；用稳定环境中的正常波动与已知视觉回归验证新方法，不能单纯扩大容差来消除失败。历史宿主快照与实时 React/Vue 对照的作用不同，不能直接互相替代。[当前门槛参考](component-contract.md#浏览器验收门槛)、[Playwright 视觉比较](https://playwright.dev/docs/test-snapshots)。

以固定 Semi 的公开契约判断测试价值，不要求旧用例、名称、数量或矩阵结构逐项保留。重复验证、废弃实现细节断言和无独立风险的组合可以删除；公开行为、必要状态、主题、方向、语言与运行环境的有效覆盖仍需说明并验证。无需先完整运行旧矩阵才允许重设计；关键风险用新测试和真实基线验证。语言会影响布局和可访问名称，dark/RTL 会影响样式，不机械裁剪这些维度。

例如 Button 在组件层保留系统性的 hover/active/focus 验证；只在语言或场景新增独立状态与集成风险时扩展用例。Modal/Select 的自定义容器、Portal 和焦点契约在组件场景中验证，不因承载这些行为的旧文档页面删除而豁免。

示例复杂度按真实能力判断：普通 List 与虚拟滚动 List 分开选批。迁移工具不承接缺失虚拟化、拖拽等功能实现，不改变未通过项的状态。

## 本地测试与证据的执行方式

CI 工作流调用本次未调整，共用的 Playwright 配置已采用新 headless。完整迁移时移除 CI 中组件单测、Storybook 交互和 Playwright 测试的自动调用，保留独立的静态检查、Node 产物验证与发布职责。组件测试使用标准 runner 在本地按影响选择范围：

| 改动                             | 本地验证范围                                              |
| -------------------------------- | --------------------------------------------------------- |
| 技能、排期、普通仓库文案         | 格式、链接、diff；不启动组件浏览器矩阵                    |
| 静态文档                         | 格式、链接与公开 API/迁移说明核对                         |
| Storybook 场景                   | 场景类型/构建与主要操作；触及共享基础设施时扩展相关组件组 |
| 组件实现                         | 组件单测及直接消费者；按实际风险补充组件对照              |
| 主题、公共组件、构建配置、锁文件 | 扩展到受影响组；影响无法可靠确定时保守运行完整相关套件    |
| 发布候选                         | 全量组件契约及实际产物门禁；共享构建只准备一次            |

用明确路径、公共入口和既有依赖关系确定受影响范围，通过标准 runner 的用例筛选与 projects 执行。不能仅凭 Git 文件名或静态导入推断所有动态依赖；不新增选测平台。主题、全局配置与锁文件等变化不能随意排除。

后续若新增站点，再按实际产品范围定义内容和集成检查。当前组件开发、测试迁移和包发布均不依赖站点、编辑器、文档映射或双语逐示例矩阵。

新体系的测试结果记录实际提交、固定 vendor revision、环境和执行范围，标准报告与诊断附件存本地已忽略目录，现行测试的快照基线继续跟踪。通过且输入未变的运行复用；未运行项不计通过，失败、跳过或 flaky 不可用于认证。构建/执行期间输入变化则本次结果不可作为最终交付证明。

旧文档报告、指纹工具、覆盖账本和 `accepted` 协议已退役；需要追溯时通过 Git 历史查看，不为维持旧协议继续运行旧验收。历史待恢复项不自动成为新体系的补跑清单，也不能自动算作通过。切换时按新体系实际验证的契约覆盖如实记录，不把旧结果冒充新结果；删除旧机制不会增加验收数量。

这是组件测试体系的目标设计。切换时依据实际覆盖与运行结果更新现有组件契约，使用标准 reporter，不新增报告协议；不会因为文档站移除就宣称新测试体系已运行通过。

## 分阶段落地与退出条件

1. **确定目标与最小验证集合。** 从固定 Semi 契约选出代表场景，复用有价值的现有计时和证据作参考。使用标准 runner 在本地按影响筛选测试；即将废弃的旧工具无需先做兼容性修补，也不先恢复历史矩阵。
2. **建立最小 Vue 标准环境。** 试运行 Vitest/VTU 与 Storybook Vue 3，核对 SFC/JSX、Node SSR、Prism、Tiptap 和 Worker 所需边界。优先使用工具原生配置，改造或删除妨碍接入的旧 aliases、构建包装和耦合；若仍需大型自研编译层，重新比较成本并调整选型，不为兼容旧入口扩建框架。
3. **从低到高验证代表场景。** 先 Breadcrumb 或 Switch，再 Popover 的容器/焦点场景，最后 Table 的已有就绪场景。复用有价值的场景和断言，按公开契约核对新测试的覆盖、失败捕获和实际结果，不要求逐项迁移废弃测试；Table 的未就绪拖拽/虚拟化问题不混入工具迁移。
4. **逐组替换或整体切换。** 选择改动更简单、总成本更低的方式，可同步删除旧 runner、测试组织和调用方，不要求长期双跑或兼容旧命令。必要的事件、异步和 SSR 语义由新测试覆盖，覆盖率按实际源码核对，不用旧用例数量或相近百分比证明质量。
5. **切换本地组件测试并清理旧体系。** 按目标契约在本地跑一次新体系完整相关检查，验证标准报告、来源和发布检查；同步修改或删除调用方，移除 CI 中组件测试的自动调用、旧调度、Vue 工作台、失去用途的报告和依赖，保留独立的静态、Node 产物与发布职责，更新现有技能与契约。

每个交付都要满足：目标所需能力完整，旧体系的非目标职责可以直接取消；必要契约和环境有有效覆盖；相关构建、文档与测试入口能实际工作；剩余缺口如实记录。对关键风险用已知回归或可丢弃的故障注入验证新测试确实会失败，不用“配置能启动”代替测试有效。

同环境、同一覆盖范围记录冷/热运行耗时、构建次数、重复状态验证次数、报告体积、失败定位与修复工作量；有必要时做一次迁移前后对照。尚无这些迁移数据，不承诺节省比例、完成时长或 token 数。只有覆盖保持且成本实测下降，才能认定方案提高了验收效率。
