## 目标

按用户确认的计划彻底移除 Astro/Starlight，根开发入口和文档构建、类型、静态产物及浏览器门禁统一使用现有 Nuxt 站点。

## 验收标准

- 正式应用、依赖与配置不再运行旧框架，页面统一在 src/pages，产物统一在 .output/public。
- 冻结 lockfile 安装、内容检查、类型检查、构建、静态门禁、Chromium 文档回归通过。
- 剩余内容/视觉验收不作为保留旧框架的前提；证据失效时据实重跑。

## 风险与假设

- 旧内容门禁依赖 MDX 与 Pagefind，必须整体替换；根 check 的内容检查移动到构建之后，确保新 checkout 有本地 REPL import map。
- pnpm 11 将 `clean` 解析为内建命令，过滤调用报 Unknown option recursive；清理统一使用显式 `run clean`，根 `typecheck:clean` 同步修正。
- 站点开发、构建和类型检查先构建公开包，确保 clean 后也可以使用发布入口；不修改公共组件 API。
- lockfile 重算报告 sass/Vite、unctx/unplugin、unctx/oxc-parser 的既有 peer 版本问题（已对照 HEAD 的包声明与 snapshot 绑定）；没有放宽 strictPeerDependencies 或新增依赖。冻结 lockfile 安装成功。

## 修改范围

- 文档默认脚本、依赖、配置、旧内容树和门禁；根脚本与工程忽略项；当前架构和使用文档。
- 旧六组件双语说明与 Nuxt 内容已对照：迁移说明/API/SSR 内容已保留或扩充；补回 IconHome 导入、Button htmlType 用法、英文 React→Vue 表和仓库 LICENSE 链接。
- Nuxt 浏览器配置成为唯一实现，保留原 :nuxt 命令和 Playwright 配置转导出供批次调用；迁入旧浏览器测试的 canonical/hreflang 断言。

## 关键决策与权衡

- 选择：直接切换 Nuxt；删除旧框架及缓存，不保留第二站点。用户明确授权此方案。
- 理由：旧“全部验收后再切换”规则与完全替代要求冲突。
- 备选：长期双框架并存不符合目标，不采用。
- 代价：公开包准备增加独立启动/类型检查耗时，换取清理构建产物后仍可运行。
- 回退：通过 Git 整体恢复应用、配置和 lockfile；没有线上部署。
