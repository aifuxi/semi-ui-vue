# Theme Studio 主题提示气泡背景修复

日期：2026-11-08。

## 问题现象

点击主题表单的“主题提示”，气泡内包含链接、正文及关闭按钮。浅色模式显示深底深字，深色模式显示浅底浅字，可读性不足；用户期望背景与当前主题匹配。

## 根因

该消费场景使用了 Tooltip 的反色背景，但内部 Typography、链接及 Button 分别使用当前主题的普通前景色。默认主题实测：浅色背景 `rgb(65,70,76)`、正文 `rgb(28,31,35)`；深色背景 `rgb(198,202,205)`、正文 `rgb(249,249,249)`。不是 Portal 没有同步模式，而是反色 Tooltip 与带操作的普通主题内容搭配错误。

## 修复方案

主题表单的富内容气泡改用现有 Popover，保留顶部定位、箭头、自定义开关及默认 body Portal。Popover 背景与箭头统一使用 `--semi-color-bg-3`，内容继续消费原来的主题前景、品牌与排版。组件库 Tooltip 默认行为及组件编辑页的 Tooltip 样例不变；不增加覆盖背景的专用 CSS。

## 验证结果

- 定向 Playwright Test：3 项通过，完整 Chromium 新 headless、3 workers、0 retries，含工作台类型检查及生产构建约 12.4 秒。
- 气泡持续打开时：浅色背景与箭头为白色、正文为深色；切为深色后背景与箭头为 `rgb(67,68,74)`、正文为浅色。编辑 `--semi-color-bg-3` 为 `#273449` 后，两者同步更新。
- 同一检查继续验证品牌、字体、字号、行高与关闭行为；局部主题隔离及顶部全局模式入口检查通过。
- 范围内 ESLint、Prettier、Changesets 和差异检查通过；开发页面导入前轮主题配置后完成明暗视觉检查。截图与日志放在已忽略的 `test-results`、`.local`。
- 未运行整库或完整 Theme Studio 回归。IDE 构建工具诊断能力有限，实际类型检查及生产构建由上述测试入口完成。

## 扩展核对：其他气泡与弹层

按用户后续要求，核对范围扩展到工作台现有浮层入口：全局/局部品牌方案、全局/局部字体、主题分类、主题状态、变量引用、对比度背景下拉；两个颜色面板及其嵌套格式菜单；主题提示 Popover；主题表单、组件预览、导出 Modal，以及独立局部主题的气泡与弹窗。没有箭头的下拉和颜色面板保持无箭头。

### 额外缺陷与修复

在组件编辑页设置 Tooltip 提示背景为 `#164e63`，深色模式实测气泡为 `rgb(22,78,99)`，箭头仍为默认 `rgb(198,202,205)`。原因是工作台私有背景 token 只映射 wrapper 的 background-color，而 SVG 通过 currentColor 单独着色。

在 token 目录的共享绑定构造函数中支持附加节点绑定，将同一个 `--studio-color-tooltip-bg-default` 同时映射到气泡背景和箭头颜色。线上预览、CSS 导出仍共用这份映射，没有修改组件库或 vendor，也没有增加特定页面的 CSS 补丁。未设置覆盖时，普通文字 Tooltip 继续使用固定 Semi 的反色背景/前景配对。

### 验证与结果

- 新增 `overlays.spec.ts` 的 15 项入口检查，配合扩展后的 Tooltip 覆盖检查及已有主题 Popover 检查，共 17 项通过；完整 Chromium 新 headless、3 workers、0 retries，含工作台类型检查和生产构建约 15.6 秒。未执行完整 Theme Studio 或整库矩阵。
- 下拉、颜色面板、嵌套菜单、Modal 均保持同一 Portal 节点打开，经历浅色→深色→浅色，断言实际背景与可见文字，而不只检查变量。通过顶部开关的 DOM click 避免 pointerdown 自动关闭面板或遮罩拦截；不访问应用私有状态。
- 主题气泡及普通 Tooltip 检查箭头；自定义 Tooltip 验证浅/深模式独立背景与文字覆盖及切回后的还原。独立局部主题不被全局切换覆盖，撤回局部边界后气泡和弹窗恢复全局继承。
