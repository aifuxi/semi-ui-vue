## 目标与验收

用户要求解决反复优化后仍然耗时的问题。本轮以已有同机完整六批 224 项通过报告为基线：总耗时 1068945ms，浏览器 928201ms。相同矩阵端到端至少缩短 50%；不删场景、断言、主题、RTL、截图和样式要求，不提高 retries。

同时交付可复用的修复路径：精准判定证据失效、按源码与产物哈希验证准备缓存、默认代表用例诊断。新鲜度异常自动重建，失败/重试/跳过或输入变化不得写 accepted。

## 范围与分工

- 浏览器：独立 context 的测试并行、有效并发参数、按实际瓶颈消除等待。
- 证据输入：按批次分离 React 适配器、真实 Foundation 依赖追踪，未知情况保守失效。
- 准备：资源/站点/检查阶段缓存，删除或篡改产物自动失效；诊断和正式入口共用。
- 入口与文档：代表用例诊断、一致的报告完整性检查、前后性能记录。

## 重要取舍

- 直接使用上一轮已保存的完整基线，不为获取相同数据再花 18 分钟跑串行基线。
- 浏览器探针集中一次运行 23 项复杂代表用例，默认先验证 3 workers；不穷举并发数消耗资源。
- 最终首次正式运行用冷缓存，之后单独记录热复用；不把预热后的时间冒充冷启动收益。
- 修改范围限文档/测试基础设施，保留现有组件源码与 vendor；不因提交重复全仓组件或发布包测试。
- 修改指纹规则后正式重跑全部六批生成新证据，不迁移旧报告。
