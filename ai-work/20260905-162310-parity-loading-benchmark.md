# AI 工作记录：浏览器测试加载性能实验

- 日期：2026-09-05
- 状态：完成（第一阶段加载实验）

## 目标

比较开发服务器、浏览器预热和预构建静态服务的场景加载成本，为后续 CI 优化选择方向。本阶段不修改组件、覆盖率、视觉阈值、重试和 flaky 门禁，也不推送或触发 Actions。

## 验收标准

- 提供可重复的本地命令，分别报告准备、预热、加载和总耗时。
- 使用相同 Chromium、场景、并发和独立 Vite 缓存比较三种模式。
- 在本地 Linux 容器重复实验；保存运行时错误和逐页面数据，不把加载成功等同于视觉对齐通过。

## 修改范围

- `scripts/benchmark-parity-loading.mjs`：独立实验工具。
- `package.json`：增加 `benchmark:parity` 入口，默认开发模式。
- 本记录：保留实验条件、结果和选择依据。

## 方法与限制

- 六个场景：Avatar、Select、Tree、Table、Typography、Pagination；light、LTR、zh-CN，1440×900、DPR 1。
- 三个场景并发，每个场景的 React/Vue 页面同时访问；同一个 Chromium 进程，每页新建 context，避免浏览器缓存掩盖服务端差异。
- 每个进程新建临时缓存和构建目录，先访问全部六个场景，再在相同服务器上重复一次；两遍共 24 个页面。
- `warm` 模式先逐场景访问并丢弃 context，单独计入预热成本。这里测的是浏览器预热，不代表测过 Vite 的全部 warmup 策略。
- `build` 直接调用 Vite build，再 preview；不包含安装依赖和类型检查成本。输出只写入系统临时目录，不覆盖现有 dist 或 dev cache。
- 每页等待工作台、真实组件节点、加载标记消失、字体和两次动画帧；记录请求数、页面错误、console error 和请求失败。60 秒是实验采样上限，不改变 Playwright 现有超时。
- 请求数截至采样结束，不等于 networkidle 后的完整网络请求数；本工具不代替现有 divider 的 200 请求门禁。
- 两个 Vite 服务通过 API 在同一个 Node 进程内运行，而 CI 使用独立进程；结果用于筛选方向，不能直接外推整套 workflow 的加速倍数。
- 本地 macOS/Linux 都为 arm64、16 个可见 CPU，非 GitHub runner 的等价环境；系统文件缓存未清除，预热/构建结果可能受到宿主其他进程影响。
- 容器 Git HEAD 仍为 `504038a`，是之前 act 的工作副本。相对该提交，当前主机 apps/packages 的生产源码只有 TooltipPortal 改动；两端该文件 SHA-256 相同（`f0fbd452f94880601c19392a5bde753992bcab9bb1ce5c1603d0a35a6af85925`）。不能把容器 HEAD 当成测试源码版本的完整证明。

## 验证证据

- 使用全局 pnpm 12.3.1，设置 `npm_config_manage_package_manager_versions=false`；没有切回项目声明的 pnpm 11。
- `node scripts/benchmark-parity-loading.mjs dev` / `warm` / `build`：macOS 三种模式各一轮成功。
- macOS 首轮总耗时：dev 8.628 秒、warm 14.121 秒、build 4.014 秒；build 其中准备 2.944 秒、加载 0.993 秒。
- Linux：通过已有 act 容器执行上述三种模式，每种三轮，全部退出 0；每种模式 72 个正式采样页面，全部未记录运行时错误，warm 另有 36 个预热页面。

| 模式  | 三轮总耗时（秒，含准备/预热） | 总耗时中位数 | 页面稳定时间 p95 | 采样请求数范围 |
| ----- | ----------------------------- | ------------ | ---------------- | -------------- |
| dev   | 15.018 / 14.488 / 14.725      | 14.725 秒    | 6.036 秒         | 46–1119        |
| warm  | 21.015 / 21.389 / 22.384      | 21.389 秒    | 2.965 秒         | 46–1119        |
| build | 4.653 / 4.732 / 4.595         | 4.653 秒     | 0.372 秒         | 12–78          |

- build 三轮准备成本 3.306 / 3.401 / 3.341 秒，正式加载阶段 1.317 / 1.293 / 1.221 秒；并非漏计构建成本后的比较。
- 原始 Linux JSON 已取回 `/tmp/semi-loading-evidence.hmPMlR/`，文件名为 `{dev,warm,build}-{1,2,3}.json`。
- 早期探测曾因 Tree/Pagination 根 class 推断错误超时，修正为真实组件选择器后重新采样；这些失败探测不纳入上表。
- 验证 package 入口时遇到实验端口占用，脚本报错而未复用未知服务器；待 Linux 实验结束后重跑。准备任务使用 allSettled，确保一侧启动失败后也能回收另一侧已创建的服务。
- `pnpm typecheck:root`：通过。
- `pnpm benchmark:parity build`：最终脚本通过，24 个页面采样完成，计入构建总计 4.023 秒，服务器正常退出。
- `pnpm exec eslint scripts/benchmark-parity-loading.mjs`：通过。
- 非法模式参数：在创建服务器前报错退出，未回退为其他模式。

## 关键决策与权衡

- 先保留可复测实验，不立即切换 CI。三轮证据更支持预构建，浏览器全量预热增加总成本；优先推进预构建的正式门禁兼容验证，再考虑分片，而非直接叠加更多 workers。
- 当前部分测试用原始源文件网络请求证明来源（包括 Vue 子路径和 React vendor 来源）；切换为静态资源后这些断言不能直接成立。后续必须提供等价的构建来源和按场景依赖证据，不能删除断言后宣布通过。
- 预构建会改变开发/生产代码路径，仍需跑现有行为、Portal、动效、computed style 和截图对照，不能仅凭页面加载成功替换正式验收。
- 分片和覆盖率合并暂未实施，避免同时改变过多变量。
- 回退：删除实验脚本和 package 入口即可，当前工作流与组件运行方式未变。
