# AI 工作记录：文档验收执行与诊断提速

- 日期：2026-09-06
- 状态：完成

## 目标

减少示例验收的重复服务启动，记录可核对的阶段耗时，并将参考契约预检、定点诊断和稳定后集中回归纳入后续流程。

## 验收标准

多批次只启动一次 Playwright；保留单 worker、测试 context 隔离、严格视觉阈值、完整矩阵及原有重试配置。任何批次失败、缺项、重试、跳过、缺少附件或全局错误不得生成新证据。实际运行全部五批验证，并核对最终 accepted 和覆盖数量。

## 风险与假设

服务复用可能暴露跨 spec 污染，须通过真实矩阵验证。批次报告拆分不能丢掉未知用例或全局错误。性能比较以同机前次运行作观察基准，非多次受控基准实验，不能直接推断长期提速比例。工作区起始干净；CodeGraph CLI 不接受指定仓库的 --path 参数，因此用精确源码与调用方调查补足，没有使用未知仓库索引。

## 修改范围

- 验收入口合并所有选中 spec 到一次 Playwright 调用，公开包/主题/站点构建仍共享一次。
- 报告拆分保留环境、截图和行为附件，按 spec 校验全部批次后再写证据；未知 spec、重复认领和全局错误直接拒绝。
- 成功/失败阶段计时记录到 acceptance-timing.json，包含总耗时、各命令耗时和最慢十次测试执行。逐批 stats.duration 记录测试运行时间总和，共享墙钟时间另存 sharedRunStats。
- 流程增加 React 原站 Provider/语言/Portal/键盘契约预检、分阶段具名诊断、有界断言与诊断模式 --retries=0 --max-failures=1。完整包验证集中到源码稳定后。

## 关键决策与权衡

选择共享服务而不提高 worker 数，先去掉确定的重复启动，避免机器资源竞争破坏视觉稳定性。没有删除依赖指纹、复用旧报告、更改阈值或修改组件运行时。本轮没有重构所有历史参考编译模块；后续新增批次按新流程优先使用专属模块，真实共享依赖变化仍须重验。回退可恢复三个执行/校验脚本及对应测试；回退后证据须按实际指纹重新验证。
