# 示例补齐与视觉验收流程改造

目标：减少重复构建和无关批次重验，并让后续任务默认沿用同一流程；保留原有视觉及行为验收标准。不推进新的组件示例，不改公开组件实现或 vendor。

## 改动与取舍

- 正式入口支持多个批次、`--affected` 和只读 `--plan`。有效证据跳过，其余批次共享一次公开 JS、主题、站点构建、类型、内容和产物检查。独立 build/typecheck 保持自行准备资源。
- 批次从 Demo 和文档外壳导入追踪 UI 依赖，保留包构建配置和共享主题/Foundation/图标输入；未知动态依赖保守扩大至全部 UI。不会把根入口的所有导出误当成按名称精确使用。
- 构建前检查 Demo 映射和 Git/磁盘大小写；运行期间校验构建源码输入和各批次指纹。pages/demos/tokens 三个生成注册表不计入冻结输入，其源内容和生成脚本仍受检查。完整报告仍拒绝失败、重试通过、跳过、缺少矩阵及附件。
- 复用公共字体/图片就绪 fixture；原有 computed style、几何、截图精度和交互断言未放宽。
- `AGENTS.md`、组件 Skill 和文档入口共同指向 `docs/documentation/workflow.md`，明确代表用例先行、稳定后集中回归和证据刷新、提交时复用未变化的已验证结果。

依赖算法目前只对 UI 与 Demo 做递归细分；主题、Foundation、图标和共享参考运行时仍保守纳入。纯类型导入不作为视觉依赖，公共类型契约变更继续执行组件级类型门禁。新增其它共享依赖必须更新批次 inputs。正式入口未提供跨进程产物缓存或不校验新鲜度的 skip-build。
