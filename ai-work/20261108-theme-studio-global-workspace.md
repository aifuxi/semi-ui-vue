# Theme Studio 全工作台主题与快速反馈

日期：2026-11-08。

## 问题现象

小幅样式调整需要等待较久才能得到交付反馈；主题只影响预览，导航与编辑面板固定为浅色；页面重复显示模式开关和固定浅色/局部深色对照。

操作入口为 `/#/tokens`：修改颜色、组件属性或切换模式，预期导航、编辑器、预览及已打开浮层同步更新。用户要求优先压缩等待，只保留顶部的全局明暗切换。

## 根因与证据

- 引用聊天最后一次调整用时约 652 秒，其中多次定向与完整测试约 86 秒，还包含原实现调查、备份和多轮浏览器操作。分钟级等待属于整个实施交付流程，不能归因于页面输入校验。
- 在现有开发服务加载全部预设、137 项浅色覆盖后连续执行 30 次 `setToken`，修改前同步校验平均约 0.75ms、最大约 1.4ms。这只测量写入路径，不包含页面绘制，不作为端到端响应时间。
- 主题边界、颜色 class 和覆盖 style 原来在 ThemePreview 内；工作台 CSS 写死浅色。局部对照还是编辑页的默认场景。
- 原值校验在 `setToken` / 文件导入与引用遍历中重复调用，引用名称又多次线性扫描目录。
- 开发期间实际观察到模块热更新后注入 Symbol 改变，子组件找不到 Provider，需要刷新。稳定注入标识可避免该类后续失配。

## 修复方案

- 将主题边界和常驻样式节点移到 App，预览自然继承；导航、编辑器、分类、状态提示等使用公开主题变量，组件绑定作用于整个工作台。
- 顶部提供一个具备可访问名称、状态和键盘操作的月亮/太阳图标开关，移除侧栏和工作区重复入口。
- 删除固定浅色对照。局部主题仅在主动进入其编辑或预览入口时展示，保持原有独立主题能力。
- 在引用遍历的提交边界一次验证原值；只有引用展开改变原值时再验证类型。名称查找复用 Map，不移除现有循环、类型及文件结构检查。
- 使用稳定注入标识；README 明确热更新先显示效果，验证不阻塞预览，小幅改动按影响选择检查，避免无依据重复全量测试。
- 原 Chrome 标签已恢复，导入前轮保存的 133 项主题备份并重新应用最新效果预设，保留原背景与填充，恢复为 137 项覆盖。

## 验证结果

- `pnpm test:theme-studio`：47 项通过，完整 Chromium 新 headless、3 workers、0 retries，总计约 30.6 秒（含工作台生产构建）。覆盖原有引用/历史/导入导出、独立局部主题、打开中的 Portal，以及 390/768/1024/1440px 布局。
- 新增实际页面检查：点击应用后只等下一绘制帧，导航、分类、编辑器与预览均已获得编辑后的背景；顶部唯一模式入口可键盘切换，跨路由和打开中的 Tooltip 同步更新。
- 首轮 46 项通过、1 项失败，定位到编辑页默认仍传入 scopes，修正默认场景后完成上述 47 项回归。
- 工作台类型检查、根工具类型检查、范围内 ESLint / Prettier、Changesets 检查和 git diff --check 通过。IDE 构建工具报告诊断能力有限，实际类型检查与生产构建作为补充证据。
- 最终视觉检查修正状态提示在浅色底上的固定白字，并通过开发页面核对提示文字、背景及明暗模式。该单项颜色修正后仅运行相应格式/差异检查和实际页面检查，没有再运行完整矩阵。
- 日志、截图和浏览器附件保留于已忽略的 `.local`、`test-results`、`playwright-report`；未运行整库回归或在线发布。
