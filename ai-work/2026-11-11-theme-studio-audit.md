# Theme Studio 全仓审计修复

## 问题现象

- 将主色设置为 `var(--studio-color-input-default-text-default)` 时，检查器接受该引用，但在线预览与 CSS 导出没有声明引用目标；继续通过私有变量引用其他私有默认变量时也有相同缺口。
- 将按钮圆角设置为 `6px`，再将公共小圆角设置为 `var(--studio-radius-button)`；复原按钮圆角后，默认值重新引用公共小圆角，形成循环，后续无关颜色编辑也被拒绝。
- 字重等无单位变量可接受 `600px`，保存后浏览器不能将其用于字重。
- 启用按钮快捷排版后，清空字号、字重或行高输入会将临时空字符串写入主题；保存的 JSON 无法通过自身导入校验。

预期：合法引用在预览与交付 CSS 中一致生效；拒绝会破坏合法会话的复原；不接受错误单位；临时空输入保留上一次有效数值，主题文件可以往返导入。

## 根因

- 引用校验按目录默认值解析私有变量，CSS 生成却只输出当前覆盖和公开颜色声明，没有补齐被引用的私有默认声明。
- 单项复原直接删除覆盖，绕过完整引用图校验；检查器复原按钮没有捕获并展示拒绝原因。
- 单位校验使用真值判断，跳过目录中表示无单位的空字符串。
- 三个按钮数值字段直接使用 `v-model`，将 InputNumber 清空时发出的临时字符串写入只应保存有效数值的主题设置。

## 修复方案

- 在当前主题边界内按依赖闭包补充被引用的私有默认声明；不写回用户覆盖与历史，也不激活未显式编辑变量的组件属性绑定。在线预览与导出继续共用生成入口。
- 单项复原先构造删除后的候选覆盖，通过引用校验后才修改会话；检查器使用与直接编辑相同的错误区域反馈，失败时保留现有设计。
- 明确检查空字符串单位，拒绝无单位变量上的 `px` 等后缀；保留原有无单位零值兼容规则。
- 三个按钮快捷字段只提交有限数值，与现有基础排版编辑器的边界一致。

范围仅为独立私有应用 `apps/theme-studio` 与其正式回归，不改变公开包 API、主题基线或版本。

## 验证结果

- 修复前以无服务 Node 最小调用复现缺失引用声明、复原后循环、错误字重单位和清空字段草稿无法导入。该检查仅核对数据与 CSS 生成，`CSS.supports` 对已知合法输入使用桩，不作为浏览器视觉证据。
- 新增 `tests/theme-studio/audit-regressions.spec.ts`，通过真实输入、检查器、文件下载和导入覆盖上述四类行为，并验证传递私有引用的独立 CSS 消费。
- 已通过：本次六个文件的 Prettier 检查、四个代码文件的 ESLint（零 warning）、`pnpm --filter @workspace/theme-studio typecheck`、`pnpm typecheck:root` 与 `git diff --check`。类型检查使用主任务已准备的公开包产物。
- IDE 文件构建返回成功，但明确提示无法收集构建诊断，不作为应用构建或行为验证证据。
- 主任务运行 `pnpm test:theme-studio`，完成一次生产构建与全部 81 项 Chromium，全部通过，退出码 0；使用项目默认 3 workers、0 retries。新增 4 项覆盖本轮问题，原有预设、双模式、组件属性、弹层、导出与页面布局回归一并通过。
- 浏览器测试使用重新构建并通过 `verify:artifacts` 的当前公开 UI 与主题包。日志为已忽略的 `.local/project-audit-theme-studio.log`；未上传或发布主题文件。

## 未覆盖边界

本次针对用户编辑、单项复原与 CSS 交付的四项确定缺陷。其他预设批量应用与已有手工引用之间的组合尚未逐项构造；本记录不宣称所有批量操作都已验证为无循环。
