# 文档验收返工防护改进

- 状态：完成
- 范围：用户要求落实上轮复盘，改进并行调度与验收工具，不启动下一批页面验收。
- 起点：WebStorm 确认工作区与 vendor 均干净，当前分支 codex/semi-docs；无 Run Configuration，使用 IDE 终端，核对各次退出码。

## 实施

1. 正式入口在读取成功证据、构建或浏览器之前检查整个请求集合的章节/API/迁移审阅与当前指纹。新增只读 `--preflight`，无浏览器证据也可检查；`--plan` 分别显示审阅与浏览器状态。指纹由既有 coverage 算法提取为共用函数，保持原字节顺序，不自动更新审阅勾选或指纹。
2. 正式 Playwright 固定零重试、首个失败即停止调度，输出 line + JSON；不改变 worker 数、用例集合或断言门槛。失败/跳过/中断报告仍不能生成任何批次证据。
3. 并行技能按复杂度与瓶颈分工，共享修复可交单一负责人；主 agent 不承担所有实现。所有写入负责人回执冻结，构建期间不并行启动消费 Nuxt 临时目录的检查。
4. 最终正文审阅和 preflight 前移到昂贵正式验收之前；诊断按根因归组，定点路径保留原前序交互，同类环境前提一次核查。准备起止、阻塞区间和返工复用现有记录，不新增报告系统。

## 验证

- `pnpm test:tooling`：88项文档工具测试与6项烟测工具测试，全部通过。
- 新增测试使用临时目录的真实正式命令，证明无证据可做只读预检、过期审阅不能被现有证据绕过、另一批审阅缺项会整组停止，且不启动构建或写证据。
- 使用锁定 Playwright CLI 执行无 browser fixture 的两个小场景：成功时全部执行；首个失败时不重试、后续用例不执行。首次测试 fixture 的 CommonJS 导入错误修正后通过，没有修改被测门槛。
- 当前 SideSheet、Table 首批 `--preflight` 退出0。实际前置检查揭示有些页面内联 API 表，没有独立 API 文件；保留原缺失标记参与指纹，并增加兼容测试，原本存在的 API 文件删除仍使旧指纹失效。
- 定点 ESLint、格式/差异与链接检查；技能 quick_validate 通过。bundled Python 缺 PyYAML，改用已安装 PyYAML 的系统 Python 验证，未安装依赖或修改环境。
