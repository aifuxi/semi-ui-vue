## 决策与验收

- 将最终 diff 自审、格式化和低成本检查前移到冻结输入之前；静态运行先通过，再执行昂贵的组件矩阵和真实包验证。
- 代表阶段增加明确退出条件；生产编译、跨源 iframe、缓存内容重开等风险按需提前验证，普通示例不强制多一次构建。
- 连续两次未解决同一失败时先补实际状态与源码证据，用最小探针验证原因；停止猜测式重试，继续已授权工作。
- 新问题只刷新失效证据，不以“一次构建”为硬上限；保留正式验收和逐组件自动提交。
- 复用现有工作记录和计时摘要汇总返工成本，不新增流程系统。效果需由后续真实批次验证，本次不宣称已减少具体分钟数。

## 场景审阅

以下为规则推演，未执行新的组件实现或浏览器矩阵：

| 情况                                  | 新流程要求                                                          |
| ------------------------------------- | ------------------------------------------------------------------- |
| 普通示例，无生产特有风险              | 开发代表通过后扩展；冻结后联合检查，不额外要求生产预检或 pack       |
| 跨源 iframe 复制/焦点或主视图退出重开 | 代表阶段验证实际交付条件，不能仅凭开发环境通过扩展                  |
| 同一定位/时序失败连续两次             | 保存相关 DOM/状态和源码证据，验证单一原因，不重跑全批或要求用户接管 |
| 只改 ignored smoke 定位器             | 产物仍有效时只跑失败阶段，稳定后恢复整批，不重建站点                |
| 冻结后发现真实运行缺陷                | 返回定点修复与 diff 自审，再按失效范围重建重验，不沿用旧结果        |
| 共享运行时影响已验收批次              | 按真实依赖重验，不修改指纹保留计数                                  |
| 仅优化本次流程文字                    | Skill/格式/链接与影响计划检查，不运行无关组件构建                   |
