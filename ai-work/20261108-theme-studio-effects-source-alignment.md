# Theme Studio 阴影与光晕原实现对齐

日期：2026-11-08。

## 问题现象

在 Theme Studio 的组件预览应用「阴影与交互」后，用户连续反馈效果过浅、范围过宽，与迭鹿原有实现不一致。原任务要求保留当前背景与填充，将来源的阴影和交互适配到现有 CSS token 体系。

复现入口为组件预览中的 Input / Select：比较 hover、focus/open 以及 Card、Popover、Modal 的投影。来源为迭鹿 `frontend/shared/styles/{common,interactions,light,dark}.css` 及其 design-spec 实际页面；来源项目不作修改。

## 根因与证据

之前实现把原主题重新设计为不同状态强度和三档投影，没有保持原始几何；后续又沿着这套自定参数增减浓度和宽度。

| 项目                     | 来源实现                                                       | 修复前实现                                    |
| ------------------------ | -------------------------------------------------------------- | --------------------------------------------- |
| hover / focus 外扩       | 均为 4px，零模糊单层                                           | 2px / 4px，曾临时扩大到 4px / 6px             |
| 单行与 Select 光晕 alpha | 浅色 10%、深色 18%，不随状态加深                               | 正常 hover 18%/28%，focus 28%/40%，校验再加深 |
| TextArea 校验            | danger-light-default / warning-light-hover                     | 与单行输入共用混色                            |
| elevated 阴影            | 浅色 1px/14px 模糊；深色 8px 下移、28px 模糊及外侧 1px 细边    | 自定三档，最大 56px 模糊；深色细边改成 inset  |
| 额外反馈                 | 只读输入保留光晕；Tooltip 无新增投影；Card 使用组件 300ms 过渡 | 排除只读，给 Tooltip 加投影，Card 改为 150ms  |

已复用运行中的迭鹿 design-spec 实测普通输入：32px 高、1px 描边，浅色 hover/focus 均为 `rgba(91,90,247,.1) 0px 0px 0px 4px`；深色 hover 为 `rgba(155,152,255,.18) 0px 0px 0px 4px`，与来源 CSS 一致。

原测试重点是背景保持和效果出现，没有用来源参数约束几何与透明度；`/4px/` 也可能匹配过渡中的 `3.42124px` 子串，不能证明已到最终状态。

## 修复方案

- 恢复统一 4px、零模糊单层光晕以及来源的 10%/18% 比例，颜色引用当前主题的焦点、危险、警告色。
- TextArea 校验独立映射到当前语义浅色，只用于 box-shadow，保留原有背景与填充。
- Card、Popover、Modal 默认共用来源的 elevated 几何与透明度；深色边缘引用当前文字色，不复制来源背景。
- 取消额外的 Tooltip 投影与 Card 过渡覆盖；只读输入恢复来源反馈，禁用、无边框及内部搜索仍排除。
- 旧效果 token 名保留，兼容已有 JSON；独立局部主题、默认对照及背景相关覆盖不变。修改前通过界面导出当前主题备份，热更新后恢复该文件，仅重新应用效果入口。
- 回归精确匹配最终 4px，比较 hover 与 focus 光晕完全相同，核对两种模式的统一浮层几何及 TextArea 例外。

## 验证结果

- 迭鹿原页面和源码调查完成；Theme Studio 实际 Select 已核对为 32px 高、1px 描边、10% 色彩的 4px 光晕，下拉为来源的 1px/14px 两层投影。
- Theme Studio 完整生产页面回归 45 项通过（Chromium，3 workers，0 retries），包括两种模式的光晕/浮层几何、背景与填充保持、局部隔离、减少动态效果及文件往返。
- 应用构建与类型检查、工具类型检查、范围内 ESLint 和格式检查通过。WebStorm 构建检查成功，但 IDE 提示构建诊断收集能力有限；实际构建以正式回归启动时的 Vue/Vite 构建为准。
- 本次不修改公共组件包或 vendor，不运行整库组件矩阵。参数、背景隔离和文件往返的自动化验证不能替代用户对整体视觉的判断。
